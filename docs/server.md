# 自建云服务器方案（VPS + 域名）

> 目标：手机在外面也能控制制冰机、改定时任务。
> 结论：**一台 1C1G 的小服务器 + 一个备案域名**就够，整套每月成本 10~20 元。

---

## 1. 两条技术路线，先选一条

| | **A. HTTP 轮询（推荐先做）** | B. MQTT 长连接 |
|---|---|---|
| 固件改动 | **零**（已有 `cloud` 命令） | 要加 MQTT 客户端 |
| 实时性 | 延迟 = 轮询间隔（建议 10 秒） | < 1 秒 |
| 功耗 | 每 10 秒醒一次射频 | 保持长连接，略高 |
| 服务器 | 一个几十行的 HTTP 服务 | 还要跑 EMQX/Mosquitto |
| 断线恢复 | 天然（下次轮询就好） | 要处理重连 |

**先做 A**：设备端一条命令接入，服务器代码我已经写好并跑通；等哪天嫌延迟大，再升级 MQTT，接口不用变。

## 2. 架构

```
   [手机 · 微信小程序 / 浏览器]
              │  HTTPS  https://ice.你的域名.com/api/*
              ▼
   ┌────────────────────────────┐
   │  Nginx（443，Let's Encrypt）│
   └─────────────┬──────────────┘
                 │ 127.0.0.1:8080
   ┌─────────────▼──────────────┐
   │  icebot-server（Node）      │
   │  · /device/sync  设备轮询   │
   │  · /api/*        镜像接口   │
   │  · state.json    状态落盘   │
   └─────────────▲──────────────┘
                 │ 设备每 10 秒 POST（出站，不需要公网 IP）
        ┌────────┴────────┐
        │  ESP32（家里）   │  联网即可，路由器不用做端口映射
        └─────────────────┘
```

关键点：**设备是主动往外连的**，所以家里不需要公网 IP、不需要端口映射、不需要 DDNS。

## 3. 买什么

| 项目 | 规格 | 价格参考 |
|---|---|---|
| 云服务器 | 1 核 1G / 2 核 2G，Ubuntu 22.04 | 轻量应用服务器活动价 ~60~120 元/年；常规 ~20~30 元/月 |
| 带宽 | 1~3 Mbps 足够（见第 8 节流量） | 含在套餐里 |
| 域名 | `.com` / `.cn` 随便 | 30~60 元/年 |
| HTTPS 证书 | Let's Encrypt | 免费，脚本自动续期 |
| 备案 | **必须**（见下） | 免费，1~3 周 |

> 选 1C1G 就够：这个服务常驻内存不到 50MB。

## 4. ⚠️ 备案是硬门槛（先办这个）

微信小程序规定：`wx.request` 的域名必须 **HTTPS + 已 ICP 备案**，并且要在小程序后台「开发管理 → 服务器域名」里登记。

- **服务器在国内**（阿里云/腾讯云/华为云）→ 可以备案，流程：域名实名 → 提交备案（个人身份证 + 服务器信息）→ 管局审核 1~3 周；
- **服务器在境外**（搬瓦工、Vultr、DigitalOcean 等）→ **备不了案**，小程序里用不了；
  - 这种情况只能：① 换微信云开发（不需要域名，见 `docs/cloud.md`）；② 或接受"只能用手机浏览器访问"。

所以：**想用小程序远程 → 买国内轻量云 + 备案域名**。如果只是自己用浏览器，境外 VPS 也行。

## 5. 部署（Ubuntu 22.04，约 10 分钟）

### 5.1 上传代码

```bash
# 本地
scp -r ice-finger-bot/server root@你的服务器IP:/opt/icebot/
```

### 5.2 一键安装

```bash
cd /opt/icebot/server
sudo bash deploy/setup.sh ice.你的域名.com
```

脚本做了这些事：

1. 装 Node 18、Nginx、certbot、ufw
2. 建 `icebot` 系统用户 + `/var/lib/icebot` 数据目录
3. 生成两个随机令牌（设备用、小程序用），写进 `/etc/icebot.env`（权限 600）
4. 装 systemd 服务 `icebot-server` 并开机自启
5. 配 Nginx 反代 + certbot 申请证书 + 强制 HTTPS
6. 开防火墙 22/80/443

结束时会把 **两个令牌** 和 **设备轮询地址** 打印出来，记下来。

### 5.3 验证

```bash
curl https://ice.你的域名.com/healthz
# {"ok":true,"up":12.3}
```

浏览器打开 `https://ice.你的域名.com/` 能看到状态页（设备还没接就是 offline）。

## 6. 设备端接入（一条命令）

串口（`pio device monitor -p COM6 -b 115200`）：

```
cloud https://ice.你的域名.com/device/sync 你记下的DEVICE_TOKEN
cloud poll 10
cloud
```

看到 `成功 N 次 / 失败 0 次, 上次 HTTP=200` 就通了。
服务器上的状态页 `online` 会变成 true。

> 功耗提示：10 秒轮询一天 8640 次、流量约 70MB/月，对电费和流量都可忽略。

## 7. 小程序端接入

1. 微信公众平台 → 开发管理 → 开发设置 → **服务器域名** → request 合法域名加
   `https://ice.你的域名.com`
2. 小程序「设置」页：
   - 设备地址填 `https://ice.你的域名.com`
   - 访问令牌填服务器上打印的 `APP_TOKEN`
3. 回到控制页，应该能看到设备状态；点「按一下」，设备 10 秒内动作。

> 小程序代码已经支持：`utils/api.js` 每次请求都带 `X-App-Token` 头，局域网模式下设备会忽略这个头，不影响原来用法。

## 8. 流量与费用估算

| 项 | 数据 |
|---|---|
| 单次轮询 | 上行 ~600 B，下行 ~150 B |
| 10 秒一次 | 每天 8640 次 → 约 6.5 MB/天 → **约 200 MB/月** |
| 带宽占用 | 平均 < 1 kbps，1 Mbps 带宽绰绰有余 |

电费按上一轮优化后 40~60mA 算，一个月不到 0.5 度。

## 9. 安全清单（很重要）

| 项 | 做法 |
|---|---|
| 两个令牌分开 | 设备令牌泄露不影响小程序令牌；反之亦然 |
| 令牌随机 | 脚本用 `openssl rand -hex 24` 生成，别用 `CHANGE_ME_TOKEN` |
| 只走 HTTPS | Nginx 强制 301 到 443 |
| 限流 | Nginx `limit_req` 10r/s |
| 防火墙 | 只开 22/80/443 |
| 状态文件权限 | `/var/lib/icebot` 归 `icebot` 用户，目录 750 |
| SSH 加固 | 禁用密码登录、改端口、装 fail2ban（可选但建议） |
| 备份 | 每天 `cp state.json state-$(date +%F).json`，保留 7 天 |

## 10. 运维命令

```bash
systemctl status icebot-server        # 状态
journalctl -u icebot-server -f        # 实时日志
systemctl restart icebot-server       # 重启
cat /etc/icebot.env                   # 看令牌
certbot renew --dry-run               # 测证书自动续期
```

## 11. 已知限制（当前版本）

1. **只镜像状态，不做设备参数下发**：云模式下能做的操作是 按一下 / 开机 / 关机 / 转角度 / 改定时任务 / 定时总开关；
   改 WiFi、校准角度这类还得局域网或串口（这些操作改的是设备本地配置，不适合远程乱改）。
2. **延迟 = 轮询间隔**：10 秒。嫌慢就降到 5 秒（流量翻倍，仍然很小）。
3. **单设备**：服务器按"一台设备"设计。要接多台，把 `state.device` 换成按 `dev` 分键的 map，改动约 20 行。
4. **没有用户体系**：靠 `APP_TOKEN` 共享密钥。给家里人用没问题，公开上线要加微信登录。

## 12. 后续升级路线

| 阶段 | 做什么 | 收益 |
|---|---|---|
| 1（现在） | HTTP 轮询 + 单设备 | 能用，零固件改动 |
| 2 | 服务器端加 WebSocket，小程序订阅推送 | 状态实时刷新，不用轮询 |
| 3 | 设备端改 MQTT（`PubSubClient`） | 按键延迟 < 1 秒，功耗更低 |
| 4 | 加微信登录 + 多设备 | 可以给朋友用 |

每一步都不破坏现有接口，`/api/*` 保持不变。
